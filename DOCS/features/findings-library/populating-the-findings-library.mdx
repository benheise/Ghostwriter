Templates can be added to the library one at a time or loaded en masse from a csv file.

<Tabs>
<Tab title="Add One FindingUpload Findings">
To add just one finding to the library, click the **Findings Library** tab on the menu bar and **Add New Finding**. This opens the finding form for documenting and submitting a single finding template.

The **Finding Guidance** field is not used in reports. Use this field to explain how a finding should be used or what evidence should be included. The field can be left blank if you do not have anything for the finding.

Use the **CVE IDs** field to list the CVE identifiers a finding covers, such as `CVE-2021-44228`. Type or paste them separated by commas, semicolons, or spaces. Ghostwriter converts them to upper case, sorts them, and drops duplicates and anything that is not a CVE identifier. The IDs are copied with the finding when you add it to a report, where you can edit them for that report.

</Tab>
<Tab title="Upload Findings">
To bulk add templates to the library, click the **Findings Library** tab on the menu bar and **Upload Bulk Findings**. This opens the upload form for your csv file. The csv file must have these headers:

_title, description, severity, impact, mitigation, replication\_steps, host\_detection\_techniques, network\_detection\_techniques, references, finding\_type, finding_guidance_

The _finding_guidance_ field is not used in reports. Use this field to explain how a finding should be used or what evidence should be included. The field can be left blank if you do not have anything for the finding.

The file may also have a _cves_ column with the finding's CVE identifiers separated by commas, semicolons, or spaces (e.g., `CVE-2021-44228, CVE-2021-45046`). The column is optional. A row with an entry that is not a CVE identifier is rejected and reported as an error. Exported findings include the column.

<Info>
If a finding (based on the _title_ field) already exists in the library, the import will update the existing record instead of discarding the data or duplicating the entry.

## Filling CVE IDs from Existing Findings

Findings written before the **CVE IDs** field existed often mention CVE identifiers in their text. The `extract_cves` management command finds the identifiers in each finding's title, description, impact, mitigation, replication steps, and references and adds them to its **CVE IDs**. Existing CVE IDs are kept. Run it with `--dry-run` first to see how many findings would change:

```bash
docker compose -f production.yml run --rm django python manage.py extract_cves --dry-run
docker compose -f production.yml run --rm django python manage.py extract_cves
```

By default, the command updates the findings library and findings attached to reports. Add `--library-only` or `--reports-only` to limit it to one of them, and `--verbosity 2` to list each finding it changes. Upgrades never run the command for you.
